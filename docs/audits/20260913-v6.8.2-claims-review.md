### F3 — "it only ever ADDS the selected rows back" (d9d7fb6, `hook-context.mjs:516`)

> "the union never renders fewer rows than the old expression did on any input
> (**it only ever ADDS the selected rows back**)"

**Verdict: the headline count claim is TRUE; the parenthetical mechanism claim is FALSE at
the sliced consumer site.**

There are two consumer sites and they differ:
- `hook-context.mjs:820` — `obsToShow`, the "### Recent" table, **uncapped**. Here the
  parenthetical holds.
- `hook-context.mjs:699-701` — `recentObs`, the "### Recent Activity" list:
  ```
  const recentObs = withFallbackTopUp(observations, fallbackObs)
    .slice(0, MIN_LOCAL_OBS)
  ```
  `withFallbackTopUp` **prepends** the selected rows (`[...observations, ...carried]`,
  `hook-context.mjs:529`), and the result is then truncated to 3. Adding to the front of a
  list that is truncated **removes** from the tail.

Exhaustive enumeration of both expressions over all ordered id-sets of size 0-4 drawn from
a 5-id universe — 42,436 input pairs:

```
input pairs enumerated        : 42436
Claim A viol (uncapped table) : 0
Claim A viol (sliced site)    : 0
Claim B viol (gain > 2)       : 0   maxGain = 2
rows evicted at SLICED site   : 3000 cases
example : {"o":[0],"f":[1,2,3],"oldRendered":[1,2,3],"newRendered":[0,1,2],"dropped":[3]}
```

With 1 selected row and 3+ fallback rows, the old expression rendered 3 fallback titles; the
new one renders 1 selected + 2 fallback. The count is unchanged (3), so the FEWER-rows claim
survives — but a row that used to be rendered no longer is, in 3,000 of 42,436 inputs.
This is the repo's own recorded pattern: a new population entering a limit-bounded window
without a ranking decision.

**Corrected wording:** "…the union never renders fewer rows than the old expression did on
any input. At the uncapped table it only adds; at the `.slice(0, MIN_LOCAL_OBS)` site the
count is preserved but the composition shifts — selected rows are prepended, so fallback
rows past position 3 are evicted."
