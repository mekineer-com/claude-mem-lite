## P2-1 — `unadopt --all` prints "no block" for a sweep that removed a block, and undercounts it

**Where:** adopt-cli.mjs:421-433, reading claudemd.mjs:314 + 369-374.

**What breaks.** `removeManaged` sets `action = 'removed'` inside the removal loop (claudemd.mjs:314),
then at :369 overrides the return with `{action:'partial', residue}` whenever `orphans > 0` — including
when a well-formed block *was* found and removed in the same call. `unadoptAll` treats every non-`'removed'`
return as the doc/state-only case:

```js
const r = removeManaged(dir, PLUGIN_SLUG);
if (r.action === 'removed') { log(`${dir} → removed`); blocks++; }
else { log(`${dir} → cleaned partial residue (detail doc/state, no block)`); ... partial++; }
```

So a project holding a real block *plus* a stray sentinel prints **"no block"** — false — and increments
`partial` instead of `blocks`. The summary then reads `removed 0 CLAUDE.md block(s) (+1 partial-residue
cleanup(s))` for a sweep that removed one. The block really is gone; only the report is wrong.

**Repro (verified):**
```
cd $W && MEM_NO_AUTO_ADOPT=1 CLAUDE_MEM_DIR=$W/memdir node probe4.mjs
```
Output: `action: "partial"`, `a real block WAS removed: true`, `user runbook survived: true`, and the
printed branch selection `"→ cleaned partial residue (detail doc/state, no block)"`.

The single-project path (adopt-cli.mjs:487) prints `r.action` verbatim, so it says `→ partial` — vague
but not false. Only the `--all` wording asserts something untrue.

## P2-3 — `hasResidue` now fires on a CLAUDE.md that merely mentions the sentinel, in a never-adopted project

**Where:** claudemd.mjs:187 (the new `orphanSentinelCount(blk.raw, slug) > 0 ||` clause) + :97-105.

**What breaks.** `orphanSentinelCount` counts sentinel *lines* as text. One mention in prose — documenting

consequences on a project the plugin has **never** adopted:

- `removeManaged` then runs anyway and unconditionally `unlinkSync`s `<dir>/.claude/plugin_claude_mem_lite.md`
  + the state sidecar (claudemd.mjs:350-357) and **`rmdir`s `<dir>/.claude/` if it is empty** (:360-365).
  Verified: an empty `.claude/` in a never-adopted project is removed.
- It prints *"Remove those lines and the text they wrap by hand"* — pointed at the user's own prose.
- It never converges: `hasResidue` is still `true` after the sweep, so every future `unadopt --all`
  re-reports the same project.

**Repro (verified):**
```

```

## P2-4 — the tightened regex makes the shipped template body load-bearing, and nothing guards it

**Where:** claudemd.mjs:79-82.

**What breaks.** The body may no longer contain the literal `<!-- claude-mem-lite:begin` or
`<!-- claude-mem-lite:end`. Today's body is clean — I measured it, 1304 bytes, **0** sentinel occurrences
(probe1.mjs), matching the docblock's claim — and the block matches itself. But **no test asserts that
property.** I grepped every `buildClaudeMdBlock` consumer: `tests/cli-path-invocation.test.mjs` checks size
and content strings, `tests/audit-r7-adopt-boundary.test.mjs` checks $HOME leakage, `tests/adopted-detection.test.mjs`
uses it as a fixture. None of them checks for a sentinel literal.

Add one to the template — documenting its own delimiters inside the steering block is a plausible edit —
and the block can no longer match itself. Measured over 6 adopts:

```
sizes after 6 adopts : 200 -> 374 -> 548 -> 722 -> 896 -> 1070
begin sentinels      : 12      end sentinels : 12
readBlock sees block : false
needsRefresh         : true   (forever)
unadopt              : partial  (cannot clean it)
```

That is byte-for-byte the unbounded-growth failure the CRLF fix exists to prevent (the docblock's own
review C1/H2). The change **relocates its trigger** from "file re-saved with CRLF" to "sentinel literal
in the template body" — a narrower trigger, but one with no guard where the old one now has `\r?\n`.

**Repro (verified):**
```
cd $W && MEM_NO_AUTO_ADOPT=1 CLAUDE_MEM_DIR=$W/memdir node probe5.mjs
```
The `control-no-sentinel-in-body` arm holds at 116 bytes across all 6 adopts; the other arm grows 174
bytes per adopt.

Suggested guard (one line, and it is the whole property):
```js
expect(buildClaudeMdBlock()).not.toMatch(/<!-- claude-mem-lite:(?:begin|end)/);
```
