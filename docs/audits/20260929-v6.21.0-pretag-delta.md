### P2-1 — A second non-ASCII sibling takes the first sibling's leftovers (and the first one's notice points at an empty id)
lib/project-rekey.mjs:111-134 (legacyIdIsExclusive), hook.mjs:2755-2758, notice hook.mjs:2775-2776.
Claims made false: CHANGELOG.md:25-27 ("Otherwise only the memories whose recorded file paths lie
inside the directory move ... Memories with no path, or only relative ones, stay under the old
id."), README.md:254-256 ("the rest stay under the old id"), README.zh-CN.md:211-213 ("其余留在
旧标识下"). Introduced by dea8ea2 (pre-range); the range reworked this path and these sentences
(043d270, 7723838, 90f4c07) and left it.

legacyIdIsExclusive only looks at rows still under the legacy id. When ~/projects/博客 and
~/projects/商城 both have path-bearing memories, the first to start (博客) does the path-proven move
(correct: 商城's paths make it non-exclusive). That move removes the only evidence of 博客, so when
商城 starts, "no stored path shows another directory" and 商城 takes EVERYTHING left under
`projects----`: 博客's pathless memories, 博客's deferred items, sessions, summaries, handoffs.
The disclosed blind spot (CHANGELOG.md:23-24, "a sibling whose memories carry no file path") does
not cover this: here both siblings carry paths.

Probe (review-delta-probes/sibling-order.mjs; real `hook.mjs session-start`, sandbox HOME):

### P3-1 — Case-exact matching (043d270) misses the directory's own paths on case-insensitive file systems, and then also blocks the whole move
lib/project-rekey.mjs:55-58 (substr = ?), :121-124 (walk compares `a.normalize('NFC') !== self`).
A stored path spelling the SAME directory with different ASCII case (Windows `c:\` vs
`C:/`, macOS `/users/me` vs `/Users/me`) is (a) not moved and (b) counted as a sibling, so the
old id reads as non-exclusive and sessions/deferred items stay behind. Before 043d270 LIKE
folded case, so the path-proven arm moved these; on Windows exclusivity could not walk `\`
paths at all (always "exclusive"). The commit fixed the Linux false positive (/home/A vs /home/a)
by creating a false negative where the FS folds case.
Probe (review-delta-probes/case.mjs):
```
win same spelling                            exclusive= true moved= 1 left= 0
win drive-letter case differs                exclusive= false moved= 0 left= 1
win user-dir case differs                    exclusive= false moved= 0 left= 1
mac (case-insensitive FS) parent case        exclusive= false moved= 0 left= 1
```
Not run on Windows/macOS; how often tool paths differ in case from CLAUDE_PROJECT_DIR there is
unmeasured. Minimum fix: in the exclusivity walk, compare case-insensitively on win32 (and treat
a same-name-different-case dir as "unknown", not "sibling").

Whether macOS hands tools NFD paths while CLAUDE_PROJECT_DIR was NFC is not verified here.
Fix: test `legacyProjectNameFromDir` of both `a.normalize('NFC')` and `a.normalize('NFD')`.
